# DIRweb — Estado do T4

Esta é a referência de passagem para quem for continuar o T4 na branch `codex/t4-integracao`. O código desta etapa está no commit `febc16d` (**Integra consultas e frontend do T4**).

## O que já funciona

- **Login e cadastro.** A tela usa a API, que autentica a conta e cria uma sessão Java. O perfil do banco define se o usuário abre a área do contribuinte ou do auditor. O Vite encaminha `/api` ao Java e o navegador envia o cookie na mesma origem.
- **Dados do contribuinte.** A tela carrega o cadastro do MySQL. O botão **Salvar dados** chama o `PUT` de atualização. Enter no campo CEP ou **Buscar CEP** consulta o ViaCEP pelo Java e preenche rua, bairro, cidade e UF. Número e complemento ficam a cargo de quem preenche.
- **Dependentes.** A aba lista os dependentes do contribuinte e carrega os tipos cadastrados no MySQL. **Salvar** no cadastro de dependente grava imediatamente.
- **Rendimentos e bens.** A fonte pagadora pode ser consultada por CNPJ ou cadastrada pela API. Os bens e os valores dos rendimentos ficam no rascunho em memória até **Enviar declaração**. O envio grava uma nova declaração e devolve o ID do banco.
- **Declarações salvas.** O Resumo consulta pelo ID. Bens e Direitos, Rendimentos e os totais do Resumo passam a exibir a declaração selecionada em modo de consulta. **Voltar ao rascunho** recupera os dados em edição.
- **Auditoria.** A Triagem lista as declarações liberadas para o perfil `auditorFiscal` e abre os detalhes com dados da API. A triagem exige sessão e perfil de auditor.

## Rotas de referência

A base do Java em desenvolvimento é `http://localhost:8080`.

| Método e caminho | Uso |
| --- | --- |
| `POST /api/irpf/login` | Cria a sessão e devolve o perfil da conta |
| `POST /api/irpf/cadastrarContribuinte` | Cria uma conta de contribuinte |

| `GET /api/irpf/contribuintes/{idPessoa}/dependentes` | Lista os dependentes do contribuinte |
| `POST /api/irpf/cadastrarDependente` | Cadastra um dependente |
| `GET /api/irpf/fontes-pagadoras/{cnpj}` | Consulta a fonte pagadora |
| `POST /api/irpf/cadastrarPessoaJuridica` | Cadastra a fonte pagadora |
| `GET /api/irpf/contribuintes/{idPessoa}/declaracoes/{idDeclaracao}/bens` | Lista os bens da declaração |
| `GET /api/irpf/contribuintes/{idPessoa}/declaracoes/{idDeclaracao}` | Consulta completa da declaração |
| `POST /api/irpf/cadastrarDeclaracaoRenda` | Envia uma nova declaração com bens e rendimentos |

## Configuração em outra máquina

1. Instale um JDK 17 ou superior, Maven, MySQL 8 e Node.js 22 com npm.
2. Em um ambiente novo ou descartável, rode o [db.sql](../backend/MyInfraAPI/src/main/resources/sql/db.sql) para criar as tabelas e depois o [popular.sql](../backend/MyInfraAPI/src/main/resources/sql/popular.sql) para inserir as 27 UFs. **O `db.sql` apaga e recria o schema `mydb`.** Se o banco já tem dados que precisam ser preservados, confira as tabelas e UFs existentes antes de executar scripts de criação ou população.
3. Copie o [database.properties.example](../backend/MyInfraAPI/src/main/resources/database.properties.example) para `database.properties` no mesmo diretório. Preencha a URL do MySQL, o usuário e a senha da sua máquina. O [.gitignore](../.gitignore) também mantém fora do Git a configuração da IDE, os arquivos `.env` locais e os arquivos gerados.
4. Para testar dependentes, cadastre no MySQL os tipos da tabela `Tipo_dependente` que forem usados na demonstração. Contas, tipos de dependência, DDDs, DDIs, endereços e declarações de teste ficam no banco local. O único conteúdo de população no `popular.sql` são as UFs.
5. Para testar **Salvar dados** com endereço no estado atual, use um CEP com endereço de referência cadastrado. O [README do backend](../backend/README.md) mostra o formato da rota de cadastro de endereço. Use os IDs reais do seu banco no exemplo. Em particular, o seed deste T4 atribui o ID `27` a `PR`. Consulte `UF` antes de aproveitar um exemplo antigo com ID `1`.
6. O cadastro pela tela cria uma conta com perfil `contribuinte`. Para testar a Triagem localmente, use uma conta de teste com `UsuarioAcesso.perfilAcesso` igual a `auditorFiscal` e faça login com essa conta.

Em um terminal, na pasta `backend/`:

```powershell
mvn clean install -DskipTests
mvn -pl MyIRPFServicos spring-boot:run
```

No IntelliJ, a alternativa é abrir o `backend/pom.xml` como projeto Maven e rodar `unioeste.DirwebApplication`. A API usa a porta `8080` por padrão.

Em outro terminal, na pasta `frontend/`:

```powershell
npm ci
npm run dev
```

Abra o endereço indicado pelo Vite. Se o Java estiver em outro endereço ou porta, copie o [.env.example](../frontend/.env.example) para `.env` e ajuste `VITE_API_URL`. A URL é usada pelo proxy do Vite. [Guia do frontend](../frontend/README.md)

## Onde retomar

1. **Salvamento de endereço por nome.** `UFDAO` já busca pela sigla. `CidadeDAO` busca por nome e UF e cadastra quando necessário. `EnderecoDAO` tem a busca e o cadastro de bairro. Faltam os equivalentes para tipo de logradouro e logradouro, a ligação de tudo ao `UCEnderecoGeralServicos.cadastrarEndereco` e o envio dos nomes pelo frontend quando o CEP ainda não tem endereço de referência no MySQL. O cadastro atual funciona com os IDs já resolvidos.
2. **Telefone editável.** O campo exibe o telefone registrado. Para salvar números pela tela, falta resolver os IDs de DDD e DDI a partir dos códigos digitados.
3. **Teste do fluxo completo no navegador.** Entre com uma conta de contribuinte, atualize o cadastro, adicione um dependente, um rendimento e um bem, envie a declaração e consulte pelo ID retornado. Depois abra a mesma declaração com a conta de auditor na Triagem.

A retomada de um rascunho salvo ficou para depois. O envio atual cria outro ID e a consulta de uma declaração já salva é somente leitura. Também ficaram pendentes as rotas de recuperação de senha, exclusão de dependente, gestão de acessos, aprovação e retenção. Recarregar a página pede novo login. **Sair** limpa a interface. O encerramento da sessão no Java depende de uma rota de logout.
